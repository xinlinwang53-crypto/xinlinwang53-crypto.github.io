01 / 17.3.1

Why maximize the margin?

A binary linear classifier assigns labels using the sign of its decision score. Many lines may separate the same points; the maximum-margin one has the most breathing room around the nearest observations.

f(x) = wᵀx + b   →   predicted class = sign(f(x))

Margin

Distance of the nearest point to the decision boundary. A larger margin makes separation more robust to small perturbations.

Support vectors

The training points that actively determine the boundary. In a hard-margin SVM they lie on the margin; points farther away usually have α = 0.

min ½ ||w||²   subject to   yᵢ(wᵀxᵢ + b) ≥ 1

Intuition first: you do not need to derive the optimization. Know why bigger margins are desirable, and remember that feature scaling matters for SVMs.

02 & 03 / SKIM

Dual problem + soft margin in 90 seconds

Dual: Instead of directly learning w, the SVM can be written using one coefficient αᵢ per training example. Its prediction formula depends on dot products xᵢᵀx. This structural change is what makes the kernel trick possible.

f(x) = Σᵢ∈S αᵢ yᵢ (xᵢᵀx) + b

Soft margin: Real data is often noisy or overlapping, so strict separation may be impossible. Slack variables ξᵢ ≥ 0 allow margin violations.

min ½||w||² + C Σᵢ ξᵢ,   subject to   yᵢf(xᵢ) ≥ 1 − ξᵢ

Large C

Violations are more expensive: the model tries harder to fit the training data.

Small C

Violations are less expensive: stronger regularization, potentially a wider margin.

Note: dual coefficients satisfy 0 ≤ αᵢ ≤ C in soft-margin SVMs. The calculus and KKT derivations are optional for this assigned reading.

04 / 17.3.4 · MAIN EVENT

The kernel trick, step by step

Problem: curved classes

A straight line in 2D cannot separate a small central cluster from a surrounding ring.

Idea: new features

Map each x into a potentially much higher-dimensional space φ(x). A linear boundary there can look curved in the original space.

K(x,z) = φ(x)ᵀφ(z)

The trick: when an algorithm only needs dot products of mapped vectors, calculate the kernel directly. You never have to compute φ(x) explicitly.

Before: f(x) = Σ αᵢ yᵢ (xᵢᵀx) + b
After:  f(x) = Σ αᵢ yᵢ K(xᵢ,x) + b

A kernel must be valid (positive semidefinite/Mercer under the usual conditions). It is not just any arbitrary similarity score. The kernel trick changes the implicit feature space, not the original labels.

Concrete algebra: polynomial kernel

For two scalar inputs a and c, consider K(a,c) = (1 + ac)². Expand it:

(1 + ac)² = 1 + 2ac + a²c²
φ(a) = [1, √2·a, a²]
φ(c) = [1, √2·c, c²]
φ(a)ᵀφ(c) = K(a,c)

Example: a = 2, c = 3 → K(2,3) = (1 + 6)² = 49. We got the 3D feature-space dot product without constructing either 3D vector.

Common kernels

Linear

K(x,z) = xᵀz

Ordinary dot product. Linear boundaries in input space.

Polynomial

K(x,z) = (xᵀz + c)ᵈ

Implicit polynomial features; degree d controls interactions.

RBF / Gaussian

K(x,z) = exp(−γ||x−z||²)

Similarity decreases with distance; often creates flexible curved boundaries.

Why it's useful

Implicit feature spaces can be very large or infinite-dimensional. Kernel functions can also be designed for structured inputs such as strings and graphs.

Kernel evaluation avoids explicitly expanding features, but kernel SVMs can still be expensive on large datasets (e.g., storing a dense N×N Gram matrix).
